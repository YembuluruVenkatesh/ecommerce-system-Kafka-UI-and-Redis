# Step 5: Verify Outbox Payload (MOST IMPORTANT)

Connect to `orderdb`:

```sql
\c orderdb
```

Run:

```sql

       payload,
       published
from outbox
order by id desc;
```

We need to see whether the payload contains:

❌ Current (bad):

```json
{"orderId":"ORD1001","product":"Laptop","quantity":2}
```

```json
{
  "eventId":"1111",
  "orderId":"ORD1001",
  "product":"Laptop",
  "quantity":2,
  "status":"CREATED",
  "createdAt":"2026-06-17T14:45:00"

```

This query is the key to solving the issue.

# Step 8: Check Consumer Exception Logs

The DLT message means the consumer threw an exception **before** processing.

Run:

```bash
docker logs inventory-service --tail 200
```

and

```bash
docker logs notification-service --tail 200
```

Look for lines like:

```text
Caused by:
The given id must not be null
```

or

```text
NullPointerException
```

---

## Most Likely Root Cause

Your consumer does:

```java
repository.existsById(event.getEventId())
```

If:

```java
event.getEventId() == null
```

the message goes to DLT.

So first run:

```sql
select id, payload, published
from outbox
order by id desc;
```

and paste the result here. That single query will tell us exactly whether the producer or consumer side is at fault.
